## 新电脑安装安卓试用包

不需要 npm 依赖、业务服务器、Metro 或 Expo 账号：

1. 直接将 APK 复制到兼容 ARM64 安卓手机，允许从所用文件管理器安装，打开“小禾学伴”。
2. 或安装 Android SDK Platform Tools，启动自己的 ARM64 模拟器/连接开启 USB 调试的设备并授权。确保 adb 在 PATH，或设置 `ANDROID_HOME`。
3. 在 `xiaohe-mobile` 运行 `node scripts/install-trial-apk.mjs`。多个设备时追加序列号，如 `node scripts/install-trial-apk.mjs emulator-5554`。脚本只覆盖安装，不卸载或清数据。

原 `启动安卓试用.command` 是原电脑专用入口，依赖已不在本目录的 `outputs/toolchain/avd/Xiaohe_Local_API36`。不要用它判断仓库不完整或应用损坏；新电脑使用上述通用入口。iPhone 无法安装 APK，Expo Go 不包含自定义 OCR 模块。

若已装过旧包，签名不一致时安装会失败；先备份原数据并核对签名，不要用卸载解决交接问题。重新构建使用新开发密钥时也可能造成这种冲突。

## 开发环境

- Node.js 建议与本次验收一致的 24 LTS；Web 最低声明为 22.13.0。使用 npm 和仓库锁文件。
- Web 的干净 clone 自动使用 portable 执行配置，可在本地模拟登录。无需原 Codex 执行环境。
- 手机使用 Expo SDK 58 / React Native 0.88，读 `xiaohe-mobile/AGENTS.md`；改 Expo API 前查匹配版本文档。
- Android 本机构建需要 JDK 17、项目锁定版本所需的 Android SDK/Build Tools/NDK/CMake。现有配置记录为 Platform/Build Tools 37、NDK 27.1.12297006、CMake 3.22.1。设置 `JAVA_HOME`、`ANDROID_HOME`，可选 `GRADLE_USER_HOME`；这些是路径，不是服务密钥。
- iOS 需要匹配 Expo SDK 的完整 Xcode 和 iOS 运行时；旧文档对原电脑版本的描述不适用于新电脑。尚无已验收 iOS 安装包。

## Web：全新数据启动

在仓库根目录依次执行：

```sh
cd xiaohe-app
npm run install:ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_great_wallop.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_melodic_alex_power.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_history_upload_fence.sql
npm run dev -- --port 5173 --hostname 127.0.0.1
```

浏览器打开终端地址，使用本地模拟登录。三个迁移只能在尚未执行的数据库上按顺序执行一次。若选择恢复历史快照，按下一节操作，跳过这些建表迁移。

## Web：恢复历史试验数据

先读 [数据说明](../handoff-data/README.md)。在任何服务启动前，于仓库根目录运行：

```sh
python3 handoff-data/restore-local.py
cd xiaohe-app
npm run install:ci
npm run build
npm run dev -- --port 5173 --hostname 127.0.0.1
```

脚本拒绝覆盖已有 `.wrangler/state`。已有本地数据时先关闭服务，单独备份并改名旧 state，然后恢复，不能直接删除。快照已经补齐 0002 的 history_epoch 列，勿再次执行 0000—0002。

历史数据是 13 个本地演示/验证工作区的存档，不代表真实用户数量或生产数据。旧角色与工作区身份保留，但新同事需使用本地演示身份/检查脚本查看对应角色；未将原所有者生产身份赋予同事。

## 手机开发与构建

```sh
cd xiaohe-mobile
npm ci
npm start -- --lan
```

完整 OCR 功能需要自定义原生构建，不可用 Expo Go 代替。安装依赖的 postinstall 会验证并应用 `patches/expo-print`，不能跳过或删除补丁校验。Android 构建：

```sh
npm run android:apk
```

结果在 `outputs/xiaohe-local-trial-arm64.apk`。仅 JS/TS 改动且本机已有匹配原生工程时，可加 `-- --reuse-native`。新电脑没有原生成工程时须完整构建。生成的 android/ios 目录不手工维护；自定义模块源码在 `modules/xiaohe-ocr`，必须保留。

两个工程检查：

```sh
# xiaohe-mobile
npm run typecheck
npm run lint
node scripts/sync-local-domain.mjs --check
npm test
# xiaohe-app
npx tsc --noEmit --incremental false
npm run lint
node --experimental-strip-types --test tests/*.test.ts tests/*.test.mjs
npm run build
```

共享领域运行时已内置到手机目录，但校验/生成需要相邻 `xiaohe-app/lib`。不要手改 `src/local/shared`，在 Web 纯领域源修改后同步并复验两端。

## 部署、账号和资源接手

当前 Web 使用 Sites 网关认证、Cloudflare Workers/D1/R2。`.openai/hosting.json` 是原项目资源标识，不包含可直接接管原账号的密钥。`outputs/access-deployment.json` 保存的旧站点部署发生在 2026-10-26，对应旧提交 `31b8331`；它不是最新手机/Web 功能已经发布的证据。

同事需要单独取得原 Sites 项目管理权限/原生产数据管理权限，或在新组织账号创建资源并修改绑定与身份方案。现有代码依赖可信网关注入身份，不能直接开放一个无网关保护的公网 worker 作为完整生产服务。GitHub 仓库访问权限不等于 Sites、Cloudflare、域名、签名、Apple/Google 商店或其他付费账号权限。

正式原生 App 的业务登录、云同步、服务端可信判分尚未实现；不得把共享站点密钥放入 App。`com.xiaohe.studycompanion` 是开发占位包名，EAS 配置是模板。正式签名/商店账号及中国大陆网络可达性需要下一阶段确认。
