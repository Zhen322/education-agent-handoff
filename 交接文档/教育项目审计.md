## 两个工程的关系与技术边界

- 手机：Expo `~58.0.19`、React Native `0.88.0`、React `19.3.0`、TypeScript `~6.0.3`、Expo Router。学习档案是本机 SQLite `xiaohe-learning-local-v1.db`，照片在 App 私有 Documents 中。无需业务账号、业务服务器或云端密钥。
- Android OCR：bundled `com.google.mlkit:text-recognition-chinese:16.0.1`；iOS 使用 Vision / CryptoKit / ImageIO。自定义模块不在 Expo Go 中，完整功能必须原生构建。iOS 源码存在但未原生编译/运行验收。
- Web：Next `16.3.4` / Vinext `1.0.0-beta.5` / React `19.2.6` / Vite `8.0.13` / Cloudflare Workers、D1、R2、Drizzle。`.openai/hosting.json` 保留 `DB`、`BUCKET` 绑定及已有 Sites 项目标识（标识不是 API 密钥）。
- `xiaohe-app/lib/` 是共享纯领域源；手机 `src/local/shared/` 是同步得到的副本和 SHA-256 来源清单，脚本只加入 Hermes 的 structuredClone 替代导入。
- `src/local/README.md` 开头仍写“没有 OCR”，与最新主 README 和模块实现矛盾，属于旧说明，交接应明确以最新 OCR 验收为准。
- 学伴目前使用审核题库的提示/讲解，普通文字是笔记；未接入生成式 AI 或语音。不要称已完成通用教育 AI 智能体。

### Android 安装与重建

- 已有包可复制到 ARM64 安卓设备安装；连接设备时使用 Android SDK 的 `adb install -r <APK路径>`，覆盖安装保留数据需要签名兼容。
- `npm run android:apk` 先校验补丁，检查 Java/SDK，再 `npx expo prebuild --platform android --no-install` 和 Gradle assembleRelease；检查 R8/OCR 守卫后才复制 APK。
- 只有 JS/TS 改动且已有匹配生成工程时可 `npm run android:apk -- --reuse-native`。
- 现有本机构建约定：JDK 17、Android Platform / Build Tools 37、NDK 27.1.12297006、CMake 3.22.1；属于项目记录，换机需检查实际可用 SDK。
- `JAVA_HOME`、`ANDROID_HOME` 可指定工具链；否则脚本寻找不存在的 `outputs/toolchain/`。Gradle 缓存可用 `GRADLE_USER_HOME`。
- `npm run android:trial` 强制使用 `outputs/toolchain/avd` 下 `Xiaohe_Local_API36` 和端口 5584；仅设置 `ANDROID_HOME` 并不能补齐 AVD，需新建隔离模拟器或直接装包。
- 生成工程内仅见 `android/app/debug.keystore` 开发签名文件，无正式 signing key。为未来覆盖旧包的试验，应专门验证签名一致性/备份开发签名，不将其描述为正式发布凭证。
